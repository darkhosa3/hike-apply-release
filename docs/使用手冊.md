# 入園申請小幫手 使用手冊（v1.4.0）

給測試者：這份文件說明怎麼裝、怎麼操作、送出後去哪看結果、出錯怎麼辦。
程式會自動填臺灣登山申請一站式服務網（hike.taiwan.gov.tw）與警政署入山申辦系統的表單。

---

## 1. 系統需求

- Windows 10／11（64 位元）
- 能連網（站台 + Gmail 收信）
- 第一次執行會下載 Chromium 約 150 MB（只下一次）
- 不需要安裝 .NET、不需要 Python

## 2. 下載與第一次執行

1. 到**公開下載專區**（不含原始碼，只有程式與手冊）：
   https://github.com/darkhosa3/hike-apply-release/releases
   下載 `hike-apply-v1.4.0-win-x64.exe`。
2. 核對 SHA256（右側 Details 或用 PowerShell）：
   ```powershell
   Get-FileHash .\hike-apply-v1.4.0-win-x64.exe -Algorithm SHA256
   ```
   預期值：`64A309321E3576EBFA740CC989DF05A1F44800513A898FA7F8EAEC3968679A4A`
3. 直接雙擊執行（單檔，不需安裝）。
4. **第一次請按「安裝瀏覽器」**：會自動下載 Chromium 並設定路徑，完成後不必再按。
5. 程式資料放在 `%LOCALAPPDATA%\入園申請\`
   - `logs\`：所有執行記錄（回報問題請附這裡的檔案）
   - `browsers\`、`Resources\`：瀏覽器與驗證碼辨識模型

## 3. 準備一個「行程資料夾」

一個行程 = 一個資料夾，裡面放：

| 檔案 | 必要 | 內容 |
|---|---|---|
| `申請人資料.txt` | ✅ | 名單，格式見下 |
| `申請日期.txt` | ✅ | 例：`11/05` 或 `11/05-11/08`（西元年看 trip.json） |
| `trip.json` | 建議 | 路線、年份、領隊、留守人 |
| `登山計劃書.txt` | 選用 | 沒指定路線時用來比對；也是入山的計畫書來源 |
| `入山地點.txt` | 選用 | 每行一個完整入山地點，最多 2 筆（`#` 開頭是註解） |

`申請人資料.txt` 範例（每個人一段，`>>` 開頭；第一段是領隊之外的隊員也可以，順序不影響）：

```
>>姓名
身分證號
手機
出生日期(1980/1/1)
縣市
鄉鎮市區
地址
Email
緊急聯絡人 姓名 電話
```

`trip.json` 範例：

```json
{
  "route": "2~9天(東埔/玉里林道–馬博拉斯橫斷–東埔/玉里林道)",
  "year": 2026,
  "leader": "領隊姓名",
  "stay": { "name": "留守人姓名", "mobile": "09xx", "tel": "09xx", "email": "xxx@gmail.com" }
}
```

> ⚠️ 這些檔案含個人資料，程式已把它們列入 `.gitignore`，**不會進版控**。請自行保管。

## 4. 圖形介面操作

1. **選路線**：下拉有 67 條（園區｜路線名稱），或直接打路線名稱。
   不確定路線時，把 `登山計劃書.txt` 丟進來，程式會自動比對。
2. **選日期**：站台可選範圍通常是「今天＋若干天」起算；超出範圍會提示。
3. **載入行程資料夾**：按鈕選資料夾，程式會帶入名單與日期。
4. **送出**：
   - 「送出申請」＝正式送件
   - 「存草稿」＝只存不送
5. 送完畫面會顯示**申請編號**（`Y` 開頭）。
6. 測試用：介面可一鍵帶入「虛構測試人設」，用假資料跑流程、送完即可取消，不會動到你自己的名額。

## 5. 服務時段（重要）

站台 **每天 23:00 ~ 隔日 07:00 暫停受理申請**：

- 在時段內按「送出」，程式會**自動降級成存草畫**，並在記錄註明可送出時間。
- 測試需要強制送件時，設環境變數 `HIKEAPPLY_IGNORE_WINDOW=1`（僅測試）。

## 6. 入園送件 → 自動辦入山（v1.4.0 起）

- `送出` 成功後，程式**接著自動申請警政署入山證**（同一支程式、同一個瀏覽器）。
- 只存草稿**不辦**；比對不到入山地點（不需入山證）會自動略過。
- **入山地點**依序取：
  1. 行程資料夾的 `入山地點.txt`（每行一筆，最多 2 筆）
  2. 登山計劃書自動比對
  3. 環境變數 `HIKEAPPLY_NPA_PLACE2` 指定第二地點（橫斷跨兩鄉鎮時用）
- 想**停用**自動入山：設 `HIKEAPPLY_SKIP_NPA=1`
- 入山會寄 Email 驗證碼（6 碼）到申辦人信箱，程式會自動收信；約需 1~3 分鐘。
- 記錄以 `[入山]` 開頭，跟入園寫在同一份 log。

## 7. 命令列（可選，排程／批次用）

在 exe 所在資料夾開命令提示字元：

| 指令 | 用途 |
|---|---|
| `入園申請.exe park <資料夾>` | 自動申請（時段內自動改存草稿），含自動入山 |
| `入園申請.exe park-draft <資料夾>` | 只存草稿 |
| `入園申請.exe park-submit <資料夾>` | 送出（仍受時段限制） |
| `入園申請.exe park-plan <資料夾\|路線名>` | 分析計劃書：判斷路線、是否需入山證 |
| `入園申請.exe park-routes` | 列出 67 條路線與目前時段 |
| `入園申請.exe npa-apply <資料夾> [地點]` | 單獨補辦入山證 |
| `入園申請.exe npa-cancel <資料夾\|身分證> <序號> [email]` | 取消入山案件 |
| `入園申請.exe ocr <圖片...>` | 測試驗證碼辨識 |

環境變數總表：

| 變數 | 作用 |
|---|---|
| `HIKEAPPLY_IGNORE_WINDOW=1` | 忽略 23:00~07:00 時段限制（僅測試） |
| `HIKEAPPLY_SKIP_NPA=1` | 入園送件後不自動辦入山 |
| `HIKEAPPLY_NPA_PLACE2` | 第二個入山地點 |
| `HIKEAPPLY_HOME` | 自訂資料夾（瀏覽器／log 存放處） |
| `HIKEAPPLY_DATE_STEP` / `HIKEAPPLY_DATE_RETRIES` | 重複申請時自動順延日期的天數／次數 |

## 8. 送完去哪看結果

- **入園**：站台會給申請編號 `Y115xxxxxx`；也可到一站式服務網「資料線上異動/取消入園」
  用「申請編號 ＋ 身分證號」查詢。
- **入山**：警政署系統「進度查詢與取消作業」用身分證＋Email 查；log 裡的 `[入山] 申辦序號 …` 也可。
- **本機記錄**：%LOCALAPPDATA%\入園申請\logs\
  - `apply_out.txt`：入園＋入山完整逐步記錄
  - `_dump_*.html`：失敗時的頁面快取（除錯用）

## 9. 常見問題

| 現象 | 處理 |
|---|---|
| 「尚未安裝瀏覽器（Chromium）」 | 按「安裝瀏覽器」；公司網路可能擋 CDN，程式會自動改用備援鏡像 |
| 半夜執行只存到草稿 | 正常，站台 23:00~07:00 暫停；等 07:00 後再 `park-submit` |
| `504 Gateway Timeout` | 警政署站台偶爾逾時，重跑一次即可 |
| 驗證碼一直失敗 | 換圖重試（程式會自動試 15 次）；仍失敗可 `ocr` 指令測試辨識模型 |
| 「重複申請／日期重疊」 | 程式會自動把日期往後順延重試（預設 +7 天、最多 8 次） |
| 找不到入山地點 | 行程資料夾放 `入山地點.txt`（每行一筆），或事後 `npa-apply` 補件 |
| exe 在「命令列測試時」找不到瀏覽器 | 設 `HIKEAPPLY_HOME=%LOCALAPPDATA%\入園申請`（正式單檔免設） |

## 10. 回報問題請附

1. `%LOCALAPPDATA%\入園申請\logs\apply_out.txt`（必要）
2. 失敗時的 `_dump_*.html`
3. 路線名稱、日期、是「送出」還是「存草稿」
4. 請**先確認 log 內不含身分證／電話等個資**再寄出（必要時請自行遮罩）

## 11. 個人資料怎麼被處理

- 你的名單、日期、計劃書只存在**你自己電腦的行程資料夾與資料夾** `%LOCALAPPDATA%\入園申請\`。
- 個人資料**不進 git 版控**（`.gitignore` 已排除名單檔）、**不上傳任何伺服器**；
  程式只把資料填到兩個政府網站（一站式入園、警政署入山）— 也就是你原本要親自填的地方。
- 程式碼與文件內**不含任何真實個資**（一律假資料）。
